# Plan 07-01: Webhook Endpoints and Deliveries Migrations

## Goal
Create PostgreSQL migrations for `webhooks` (`0008`) and `webhook_deliveries`
(`0009`) using lowercase SQL, UUID v4 primary keys, and the outbox columns described in
DESIGN.md section 3. Seed one endpoint for the default business pointing at the mock sink so
`docker compose up` demonstrates delivery with no manual setup. There is no sweep, so the
deliveries table carries no `next_attempt_at`, `locked_at`, or due index.

## Proposed Changes

### 1. `minidodo-infra/src/postgres/migrations/0008_create_webhooks.up.sql`
- Table `webhooks` (registered endpoints):
  - `id uuid primary key default gen_random_uuid()`
  - `business_id uuid not null references businesses(id) on delete cascade`
  - `url text not null`
  - `signing_secret text not null`
  - `active boolean not null default true`
  - `created_at timestamptz not null default current_timestamp`
- Index:
  - `idx_webhooks_business_id` on `webhooks(business_id)`
- Seed row for the default business (mirrors the `0002` api key seed pattern,
  `on conflict (id) do nothing`):
  - `id '00000000-0000-0000-0000-000000000003'`
  - `business_id '00000000-0000-0000-0000-000000000001'`
  - `url 'http://psp:3000/webhooks/sink'` (the mock sink from plan 07-04)
  - `signing_secret 'whsec_test_secret_12345'`

### 2. `minidodo-infra/src/postgres/migrations/0008_create_webhooks.down.sql`
- `drop table if exists webhooks cascade;`

### 3. `minidodo-infra/src/postgres/migrations/0009_create_webhook_deliveries.up.sql`
- Enum `webhook_delivery_status as enum ('pending', 'delivered', 'failed')` (`failed` marks
  a delivery whose inline retries were exhausted; observability only, not re-driven).
- Enum `webhook_event_type as enum ('invoice.paid', 'invoice.payment_failed')`.
- Table `webhook_deliveries`:
  - `id uuid primary key default gen_random_uuid()`
  - `endpoint_id uuid not null references webhooks(id) on delete cascade`
  - `business_id uuid not null references businesses(id) on delete cascade`
  - `event_type webhook_event_type not null`
  - `payload jsonb not null`
  - `status webhook_delivery_status not null default 'pending'`
  - `attempts int not null default 0`
  - `last_error text`
  - `last_attempt_at timestamptz`
  - `created_at timestamptz not null default current_timestamp`
- Index:
  - `idx_webhook_deliveries_business_id` on `webhook_deliveries(business_id, created_at desc)`
    (listing and demo observability; there is no sweep query to index for).

### 4. `minidodo-infra/src/postgres/migrations/0009_create_webhook_deliveries.down.sql`
- `drop table if exists webhook_deliveries cascade;`
- `drop type if exists webhook_event_type;`
- `drop type if exists webhook_delivery_status;`

## Verification
- Run migrations via `cargo run -p minidodo-cli -- migrate`.
- Verify both tables, both enums, the foreign keys, and the seeded endpoint row
  (`select url from webhooks;`) in Postgres.
- Fails when: migrate exits non-zero, either table is absent in `\d+`, or the seed row is
  missing.
