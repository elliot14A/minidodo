# Plan 07-02: Webhook Domain Models and Signing Helper

## Goal
Implement the webhook domain types in `minidodo-core` and the HMAC-SHA256 signing helper
used by the worker to sign outbound deliveries and by the mock sink to verify them. Match
the enum and struct derive patterns already used by `PaymentStatus` and `PaymentAttempt`.

## Proposed Changes

### 1. `minidodo-core/src/models/webhook.rs`
- `WebhookDeliveryStatus` enum: `Pending`, `Delivered`, `Failed`
  (`#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, sqlx::Type, ToSchema)]`,
  `#[sqlx(type_name = "webhook_delivery_status", rename_all = "lowercase")]`).
- `WebhookEventType` enum: `InvoicePaid`, `InvoicePaymentFailed` with
  `#[sqlx(type_name = "webhook_event_type")]` and serde rename to the dotted wire values
  `invoice.paid` and `invoice.payment_failed` (`#[serde(rename = "invoice.paid")]`, and a
  matching `#[sqlx(rename = "invoice.paid")]`).
- `WebhookEndpoint` struct deriving `sqlx::FromRow`: `id`, `business_id`, `url`,
  `signing_secret`, `active`, `created_at`.
- `WebhookDelivery` struct deriving `sqlx::FromRow`: all `webhook_deliveries` columns.
- `WebhookEventPayload` struct (`Serialize`, `ToSchema`) describing the signed body:
  `id` (delivery id), `event_type` (`invoice.paid` or `invoice.payment_failed`),
  `created_at`, and a `data` object carrying `invoice_id`, `attempt_id`, `status`, and
  `psp_ref` or `error_code`.
- Backoff policy constants and a pure helper (used by the worker inline retry loop, not a
  sweep):
  - `WEBHOOK_MAX_ATTEMPTS: i32 = 5`, `WEBHOOK_BACKOFF_BASE_SECS: u64 = 1`,
    `WEBHOOK_BACKOFF_CAP_SECS: u64 = 30`.
  - `backoff_secs(attempt: i32) -> u64` returning `min(BASE * 2^attempt, CAP)` using
    checked/saturating arithmetic (no overflow, no float). The worker sleeps this long
    between inline retries. Total budget stays small since retries happen within one claim.
- Signing helpers (reuse the `sha2` crate already used for api keys, add `hmac`):
  - `sign_payload(secret: &str, timestamp: i64, body: &[u8]) -> String` returning the
    lowercase hex HMAC-SHA256 over `timestamp` bytes plus a `.` separator plus the exact
    serialized body bytes. The timestamp is bound into the signature as replay protection.
    The worker sends this as `X-Webhook-Signature: sha256=<hex>` with
    `X-Webhook-Timestamp: <unix>`.
  - `verify_signature(secret: &str, timestamp: i64, body: &[u8], signature: &str) -> bool`
    that recomputes `sign_payload` and compares against the header value with a constant
    time comparison (strip the `sha256=` prefix). Used by the mock sink in plan 07-04. The
    signing scheme is documented in DESIGN.md section 4.

### 2. `minidodo-core/src/models/mod.rs`
- `pub mod webhook;`

### 3. `minidodo-core/src/error/error_codes.rs`
- Add `WebhookErrorCode` following the `PaymentErrorCode` pattern:
  - `DELIVERY_FAILED: &'static str = "WEBHOOK_DELIVERY_FAILED"` (logged by the worker when
    the inline retry loop exhausts all attempts and the row is marked `failed`).

### 4. `minidodo-core/Cargo.toml`
- Add `hmac` to dependencies (`sha2` is already present).

## Verification
- `cargo check --all-targets` and `cargo clippy --all-targets -- -D warnings` pass clean
  (host cannot link, so check plus clippy is the local gate as in Phase 6).
- A unit assertion is not required, but confirm `backoff_secs` is monotonic up to the cap and
  never panics for `attempt` in `0..=WEBHOOK_MAX_ATTEMPTS`.
- Fails when: build errors, any clippy warning, a float appears in the backoff math, or
  `unwrap`/`expect` is present in these files.
