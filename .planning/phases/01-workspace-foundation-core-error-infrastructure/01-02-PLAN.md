# Plan 01-02: Core Error System & Common Models

## Goal
Implement `MinidodoError` in `minidodo-core` with static machine-readable error codes (`error_codes.rs`), Axum `IntoResponse` implementation returning `ErrorResponse`, and standard domain wrapper structures.

## Proposed Changes

### 1. `error_codes.rs`
Define static string constants following `gaur` conventions:
- `DatabaseErrorCode` (`CONNECTION_FAILED`, `DUPLICATE_RECORD`, `RECORD_NOT_FOUND`, `FOREIGN_KEY_VIOLATION`, `OPERATION_FAILED`, `TRANSACTION_CONFLICT`, etc.)
- `ValidationErrorCode` (`INVALID_FIELD`, `INVALID_JSON`, `REQUIRED_FIELD_MISSING`, etc.)
- `AuthErrorCode` (`UNAUTHORIZED`, `INVALID_KEY`, `REVOKED_KEY`, `FORBIDDEN`, etc.)
- `PaymentErrorCode` (`INVOICE_NOT_PAYABLE`, `CONCURRENT_PAYMENT_CONFLICT`, `IDEMPOTENCY_MISMATCH`, `PSP_COMMUNICATION_FAILURE`, etc.)
- `SystemErrorCode` (`INTERNAL_ERROR`, `SERVICE_UNAVAILABLE`, `CONFIG_ERROR`)

### 2. `error.rs`
- `MinidodoError` enum with variants: `BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `UnprocessableEntity`, `ConstraintViolation`, `DatabaseConnection`, `DatabaseError`, `Internal`, `ServiceUnavailable`.
- `ErrorResponse` struct deriving `Serialize` and `utoipa::ToSchema`.
- `impl IntoResponse for MinidodoError` returning appropriate `StatusCode` and sanitized JSON error envelope.
- `pub type Result<T, E = MinidodoError> = std::result::Result<T, E>;`

## Verification
- Unit tests in `error.rs` verifying HTTP status mapping and JSON response format.
