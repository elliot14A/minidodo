# Plan 01-01: Cargo Workspace, CLI Harness & Docker Infrastructure Setup

## Goal
Set up the Cargo workspace with `minidodo-cli` entrypoint (using `clap` subcommands for `server` and `migrate`), scaffold `minidodo-core`, `minidodo-infra`, and `minidodo-server` matching `gaur` architecture, and provide the initial `Dockerfile` and `docker-compose.yaml` for PostgreSQL and the API server.

## Proposed Changes

### 1. Root `Cargo.toml`
Define `[workspace]` with active members:
- `minidodo-cli`
- `minidodo-core`
- `minidodo-infra`
- `minidodo-server`
Define `[workspace.dependencies]` with `tokio`, `axum` (0.8), `sqlx` (0.8), `clap` (derive), `serde`, `serde_json`, `uuid`, `chrono`, `tracing`, `tracing-subscriber`, `snafu`, `utoipa`, `validator`, `sha2`, `hmac`, `hex`, `reqwest`, `tower-http`, `dotenvy`.

### 2. Unified CLI (`minidodo-cli`)
- `minidodo-cli/src/main.rs`: Loads `minidodo.env` and parses `MinidodoCli`.
- `minidodo-cli/src/cli.rs`:
  ```rust
  #[derive(Parser, Debug)]
  #[command(version = "0.1.0", about = "minidodo invoice & payment service")]
  pub struct MinidodoCli {
      #[command(subcommand)]
      pub command: Option<MinidodoCommands>,
  }

  #[derive(Subcommand, Debug, Default)]
  pub enum MinidodoCommands {
      #[default]
      Server,
      Migrate,
  }
  ```
- Subcommand runners in `minidodo-cli/src/commands/{server.rs, migrate.rs}`.

### 3. Dockerfile & docker-compose.yaml
- Multi-stage `Dockerfile` compiling `minidodo-cli`.
- `docker-compose.yaml` running `postgres` and `server`.
- `minidodo.env.example` with environment variables.

## Verification
- `cargo check --workspace` compiles cleanly.
- `cargo run -p minidodo-cli -- --help` displays `server` and `migrate` commands.
