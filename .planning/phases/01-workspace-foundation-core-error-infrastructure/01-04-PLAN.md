# Plan 01-04: Axum Server Harness, Middleware & OpenAPI Setup

## Goal
Implement the Axum HTTP server harness for `minidodo-server` (following the exact `gaur` http serve pattern), `TraceLayer` instrumentation, `ValidatedJson<T>` validation extractor, standard `JsonResponse<T>` envelope, health check route, and root `utoipa::OpenApi` documentation.

## Proposed Changes

### 1. `minidodo-server/src/http/middleware/validator.rs`
- `ValidatedJson<T>` extractor wrapping `validator::Validate`.
- Formats field validation errors and returns `MinidodoError::BadRequest` with `ValidationErrorCode::INVALID_FIELD`.

### 2. `minidodo-server/src/http/routes/v1/mod.rs`
- `JsonResponse<T>` struct deriving `Serialize` and `utoipa::ToSchema`:
  - `success(data: T) -> Self`
  - `with_message(data: T, message: impl Into<String>) -> Self`
  - `impl<T: Serialize> IntoResponse for JsonResponse<T>`
- Health check handler `GET /health` -> 200 "OK".
- Root `#[derive(OpenApi)] pub struct ApiDoc` aggregating routes and security schemes.

### 3. `minidodo-server/src/serve.rs` & `http/serve.rs`
- Exposes `pub async fn serve(...) -> Result<()>` for CLI invocation.
- Configures `TraceLayer` (generating request UUIDs, latency logging), `CorsLayer`, and mounts `SwaggerUi::new("/swagger-ui").url("/api-docs/openapi.json", openapi)`.
- Applies `NormalizePathLayer::trim_trailing_slash()` to API routes and mounts via `.fallback_service(api)`.

## Verification
- `cargo check --workspace` and `cargo test --workspace` succeed.
- Starting `minidodo-cli server` responds to `GET /v1/health`, `GET /api-docs/openapi.json`, and serves `/swagger-ui/` (200 OK).
