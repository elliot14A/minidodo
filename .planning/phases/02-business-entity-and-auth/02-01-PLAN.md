# Plan 02-01: Business & API Key Migration with Deterministic Seed

## Goal
Create separate PostgreSQL migrations defining `businesses` (`0001_create_businesses`) and `api_keys` (`0002_create_api_keys`) tables with lowercase SQL, indexing, and seed a default business (`Acme Corp`) with a deterministic development API key (`dodo_test_key_12345`).

## Proposed Changes

### 1. `minidodo-infra/src/postgres/migrations/0001_create_businesses.up.sql`
- `create table if not exists businesses (id uuid primary key default gen_random_uuid(), name varchar(255) not null, created_at timestamptz not null default current_timestamp);`
- Seed single default business: `id = '00000000-0000-0000-0000-000000000001'`, `name = 'Acme Corp'`.

### 2. `minidodo-infra/src/postgres/migrations/0002_create_api_keys.up.sql`
- `create table if not exists api_keys (id uuid primary key default gen_random_uuid(), business_id uuid not null references businesses(id) on delete cascade, token_hash bytea not null unique, token_prefix varchar(32) not null, name varchar(255) not null default 'default', created_at timestamptz not null default current_timestamp);`
- Indexes: `idx_api_keys_business_id`, `idx_api_keys_token_prefix`.
- Seed default dev API key for Acme Corp (`dodo_test_key_12345` with SHA-256 hash `8696e7364a6dc2bbf59bd9a49ab245a0434e286918c046a36e1a8642525daf0a`).

## Verification
- Run database migrations via `minidodo-cli migrate`.
- Check tables `businesses` and `api_keys` exist and default seed rows are inserted.
