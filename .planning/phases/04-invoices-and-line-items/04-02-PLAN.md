# Plan 04-02: Invoice Domain Models, State Machine Transitions, and Database Actions

## Goal
Implement `Invoice`, `InvoiceState`, and `LineItem` models in `minidodo-core` with server-side integer cents validation, alongside granular actions in `minidodo-infra` implementing status-conditional guarded transitions and domain-specific state transition conflict errors.

## Proposed Changes

### 1. `minidodo-core` Domain Models & Error Enhancements
- `InvoiceState` enum: `Draft`, `Open`, `Processing`, `Paid`, `Void`, `Uncollectible` (`#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, sqlx::Type, ToSchema)]`).
- `Invoice` and `LineItem` structs deriving `sqlx::FromRow`, `Serialize`, `Deserialize`, `ToSchema`.
- `InvoiceWithLineItems` composite struct.
- `NewLineItem` and `NewInvoice` models with integer cents computation: `total_cents = sum(quantity * unit_amount_cents)`.
- `UpdateInvoiceState` enum specifying legal guarded target states: `Open`, `Void`, `Uncollectible`.
- Add `InvoiceErrorCode::INVALID_STATE_TRANSITION` (`"INVOICE_INVALID_STATE_TRANSITION"`).
- Add `MinidodoError::InvalidStateTransition { message, current_state, requested_state }` rendering:
  ```json
  {
    "message": "cannot mark invoice as 'open': invoice is in terminal state 'void'",
    "code": "INVOICE_INVALID_STATE_TRANSITION",
    "current_state": "void",
    "requested_state": "open"
  }
  ```

### 2. `minidodo-infra` Database Actions
- `actions/invoices/create.rs`: `create` transactional insert of invoice and line items returning `InvoiceWithLineItems` (starts in `draft`).
- `actions/invoices/get.rs`: `get_by_id` fetches invoice and associated line items scoped to `business_id`.
- `actions/invoices/list.rs`: `list_by_business` paginated list supporting optional filter by `state` and `customer_id`.
- `actions/invoices/update_state.rs`: `update_state(pool, business_id, invoice_id, target_state)` guarded transition:
  - Guard conditions:
    - Target `open`: requires current `draft`
    - Target `void`: requires current `open`
    - Target `uncollectible`: requires current `open`
  - Runs status-conditional update: `UPDATE invoices SET state=$1 WHERE id=$2 AND business_id=$3 AND state=$4 RETURNING *`
  - If 0 rows updated, queries current invoice (tenant-scoped):
    - If not found -> returns `404 Not Found` (`MinidodoError::NotFound`)
    - If found with different state -> returns `409 Conflict` with `MinidodoError::InvalidStateTransition { message: format!("cannot mark invoice as '{}': invoice is in state '{}'", target_state, current_state), current_state, requested_state }`
